# Frontend Patterns

Cross-surface UI conventions: the admin-only dashboard surface and the shared Calm Fresh design system. Referenced from `CLAUDE.md`.

## Admin-Section Patterns

Drei zusammenhängende Konventionen für Admin-only-UI im Dashboard, gh #53/#54. Backend bleibt mit `requireAdmin`-preHandler auf jeder `/api/admin/*`-Route die echte Grenze — diese Patterns sind reines UX:

- **Route-Gate via `adminOnly: true` + Router-Substitution.** `dashboard/src/router.ts`'s `createRouter` akzeptiert `{ isAdmin: () => boolean, renderAdminForbidden: RouteRenderer }`. Routes mit `adminOnly: true` werden in `buildNav()` via `visibleRoutes()` (in `admin-nav.ts`) für non-Admins ausgefiltert. Direct-URL-Zugriff auf eine adminOnly-Route ohne Admin substituiert der Router den `renderAdmin403`-View statt der eigentlichen Renderer-Funktion. Single „Admin"-Entry oben in der Topbar → `/admin` overview-Page; Sub-Pages (`/admin/users`, `/admin/stats`, `/admin/feedback`) sind nur via Quick-Nav von /admin aus oder über Direct-URL erreichbar.
- **Active-Nav-Highlight via `dashboard:rendered`-CustomEvent.** Router dispatched nach jedem `render()` ein `dashboard:rendered`-CustomEvent auf `window` (mit `detail: { path }`). `main.ts` lauscht → `updateActiveNav()` setzt `.active` + `aria-current="page"` auf den Nav-Link, dessen `href` der aktuellen `location.pathname` entspricht. Erspart Tight-Coupling Router → Nav-Modul; jedes andere Nav-adjacent-Modul kann sich an dasselbe Event hängen ohne Router-Änderung.
- **Reusable Confirm-mit-Reason-Modal.** `dashboard/src/components/confirm-with-reason.ts` → `Promise<string|null>` (resolved zur Reason auf Confirm, zu `null` auf Cancel/Escape/Backdrop-Click). Single-DOM-Slot (`#admin-modal-backdrop`; vorherige Instanzen werden vor Open abgeräumt), Reason ≥ 10 Zeichen (trim-aware, isolierter `reasonIsValid()`-Helper, 8 Vitest-Cases). Confirm-Button bleibt disabled bis Reason valid. Pflicht-Pattern für ALLE destruktiven Admin-Aktionen (Suspend, Promote, Demote, Delete). Backend's eigene Reason-Validation ist asymmetrisch: `PATCH /api/admin/users/:id` toleriert leeren reason, `DELETE` erzwingt non-empty — die Client-Min-10-Char-Schwelle ist strenger als beide, was OK ist (UX-Defence).

`/api/me.admin: boolean` ist seit 2026-05-22 die einzige Quelle für die client-side-isAdmin-Entscheidung. Anonymous-User (401) und Network-Errors collapsen beide zu `isAdmin=false` (UX-safe default). Sessions vor dem Bump können das Feld fehlend haben — TypeScript-Client behandelt `undefined` korrekt als false. Backend's `requireAdmin` ist davon unabhängig (liest `account.admin` direkt aus DB pro Request).

## Calm Fresh Aesthetic (Design-System)

Seit dem Redesign 2026-06-03/04 (Spec + Plan unter `docs/superpowers/{specs,plans}/2026-06-03-unified-green-design-system*.md`) tragen alle UI-Surfaces dasselbe **Calm Fresh** Aesthetic: frisches Emerald/Mint, runde Ecken, Cards mit weichen Schatten, prominenter Hero, mono Eyebrow-Labels als sachlicher Anker. Es ersetzt das frühere amber „Engineering-Brief"-Aesthetic (2026-05-23). Eigenschaften, die zusammen stabil bleiben müssen — wer hier etwas ändert, fasst das vollständige Set an oder konsistent gar nicht:

- **Alle CSS-Surfaces in Sync**: `viewer/src/styles.css` (Viewer-App), `viewer/public/topbar-footer.css` + `viewer/public/legal/style.css` + `viewer/public/download/style.css` (statische Marketing-Pages), `viewer/public/matomo-consent.css`, `viewer/public/feedback-fab.css`, `dashboard/src/styles.css`, und der inline `<style>`-Block in `sharer/index.html` (Tauri-Webview). Die Token-WERTE MÜSSEN in allen identisch sein — kein Vite-Variable-Sharing (Marketing-Pages + sharer-Webview laden außerhalb des Bundles). Cross-Surface-Token-Konsistenz ist Teil der Definition of Done.
- **Design-Tokens (light)**: `--paper #f6faf8` (grünstichiges Fast-Weiß), `--surface #ffffff` (Cards), `--ink #0f1f1a`, `--muted #5b6b64` (Sekundärtext), `--brand #10b981` (Emerald-Akzent), `--brand-2 #34d399` (Mint — Hero-Gradient + Highlights), `--brand-strong #047857` (Button-BG + Links, AA-auf-Weiß), `--ink-on-brand #06231b` (Text/Icons AUF Brand-Backgrounds), `--line #e3ece8` (Hairlines/Divider), `--focus #10b981`. Shape/Depth: `--radius-card 16px` / `--radius-input 12px` / `--radius-pill 999px` (Buttons) / `--radius-sm 10px`; `--shadow-sm` + `--shadow-lift` (weich, grün-getönt). Legacy-Bridges (`--accent`/`--amber`/`--cyan`/`--card-bg`/`--text`/`--text-secondary`/`--border`/`--rule`/`--edge` …) zeigen auf die neuen Tokens, damit alte Selektoren/Snippets nicht brechen.
- **Dark-Mode (hand-getunt, NICHT invertiert)**: `@media (prefers-color-scheme: dark)` setzt grün-getöntes `--paper #0c1714`, `--surface #11201c`, `--ink #e8f1ec`, `--muted #9fb2aa`, `--line #20312b`, und — wichtig — `--brand` UND `--brand-strong` werden zu `#34d399` (helles Mint). **Footgun:** jedes Element mit `background: var(--brand)`/`var(--brand-strong)`, das Text oder Icons trägt, MUSS `color: var(--ink-on-brand)` setzen — weißer Text auf hellem Mint failt WCAG-AA in dark. Gilt auch für Hover-/Active-States, die den Background auf `--brand` wechseln (das war die Quelle der Code-Review-Findings beim Redesign).
- **AA-Guard im Test**: `viewer/tests/design-tokens.test.ts` pinnt die Kontrast-Entscheidung in light UND dark (`brand-strong`/white bzw. `ink-on-brand`/`brand-strong`, plus `ink`/`paper` ≥ 4.5:1). Bei jeder Palette-Änderung dort gegenchecken.
- **Self-hosted IBM Plex (latin-subset)**: unverändert — 4 woff2 (`IBMPlexSans-Regular.woff2`, `-SemiBold.woff2`, `IBMPlexMono-Regular.woff2`, `-Medium.woff2`, ~76 KB) unter `viewer/public/fonts/` UND `dashboard/public/fonts/` (eigene Kopien — separate nginx-Container; die sharer-Webview bündelt ihre eigene). Keine Google-Fonts-CDN (CLAUDE.md-no-Tracker-Rule). Neue Varianten: latin-Subset von `https://cdn.jsdelivr.net/npm/@fontsource/ibm-plex-sans/files/` (oder Mono-Pendant), Kopien gleich halten. Tokens: `--font-sans` ("Plex Sans") für Fließtext/Headlines, `--font-mono` ("Plex Mono") für Daten + Eyebrow-Labels.
- **Class-Name-Preservation**: Beim Recast wurden NULL Klassennamen + IDs umbenannt, nur Visuals recast. Konsequenz: existierende Tests + Selektoren (Playwright, vitest jsdom-Queries, Tauri-TS) bleiben grün. Neue Komponenten gerne mit neuen Klassen — bestehende NICHT umbenennen ohne den vollen Test-Tree neu zu syncen.

Visuelle Marker, an denen man das System erkennt: runde Ecken (Radius-Tokens) überall, weiche Card-Shadows statt scharfer Ink-Rules, `--surface`-Cards mit 1px `--line`-Border (+ Hover-Lift), Pill-Buttons (primary = `--brand-strong`-Fill + `--ink-on-brand`-Text), prominenter runder Hero auf den Home-Pages (`.hero` mit Mint→Paper-`color-mix`-Gradient + `.hero-title`), mono tracked-Caps `.eyebrow`-Labels (der „sachliche" Anker), emerald **runder Bar**-Heading-Marker (`h2::before { content: ""; width: 4px; height: 1em; border-radius: var(--radius-pill); background: var(--brand); }` — ersetzt den früheren amber `▌`-Glyph), und die CSS-counter-basierte `[01]`/`[02]`-Nav-Nummerierung im Dashboard (jetzt emerald).
