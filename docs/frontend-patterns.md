# Frontend Patterns

Cross-surface UI conventions: the admin-only dashboard surface and the shared Dark Engineering design system. Referenced from `CLAUDE.md`.

## Admin-Section Patterns

Drei zusammenhängende Konventionen für Admin-only-UI im Dashboard, gh #53/#54. Backend bleibt mit `requireAdmin`-preHandler auf jeder `/api/admin/*`-Route die echte Grenze — diese Patterns sind reines UX:

- **Route-Gate via `adminOnly: true` + dreistufiger Router-Substitution.** `dashboard/src/router.ts`'s `createRouter` akzeptiert `{ isAdmin, isLoggedIn, isSessionResolved: () => boolean, renderAdminForbidden: RouteRenderer }`. Routes mit `adminOnly: true` werden in `buildNav()` via `visibleRoutes()` (in `admin-nav.ts`) für non-Admins ausgefiltert. Direct-URL-Zugriff auf eine adminOnly-Route wertet der Router in drei Stufen aus: Session-Probe noch offen → neutraler „Lade …"-Platzhalter (kein `<h1>`, damit `focusNewView` nicht auf eine Seite springt, die gleich ersetzt wird); ausgeloggt → `history.replaceState` auf `/login` (kein 403 — eine abgelaufene Admin-Session ist kein „kein Admin"-Fall); eingeloggt ohne Admin → `renderAdmin403`. `session.ts` feuert `onSessionChange` auch beim ersten (auflösenden) Probe, selbst wenn der Zustand anonym bleibt; `main.ts` ruft dann `router.refresh()`, wenn die aktuelle URL per `isAdminGatedPath()` gegated ist. Single „Admin"-Entry oben in der Topbar → `/admin` overview-Page; Sub-Pages (`/admin/users`, `/admin/stats`, `/admin/feedback`) sind nur via Quick-Nav von /admin aus oder über Direct-URL erreichbar.
- **Active-Nav-Highlight via `dashboard:rendered`-CustomEvent.** Router dispatched nach jedem `render()` ein `dashboard:rendered`-CustomEvent auf `window` (mit `detail: { path }`). `main.ts` lauscht → `updateActiveNav()` setzt `.active` + `aria-current="page"` auf den Nav-Link, dessen `href` der aktuellen `location.pathname` entspricht. Erspart Tight-Coupling Router → Nav-Modul; jedes andere Nav-adjacent-Modul kann sich an dasselbe Event hängen ohne Router-Änderung.
- **Reusable Confirm-mit-Reason-Modal.** `dashboard/src/components/confirm-with-reason.ts` → `Promise<string|null>` (resolved zur Reason auf Confirm, zu `null` auf Cancel/Escape/Backdrop-Click). Single-DOM-Slot (`#admin-modal-backdrop`; vorherige Instanzen werden vor Open abgeräumt), Reason ≥ 10 Zeichen (trim-aware, isolierter `reasonIsValid()`-Helper, 8 Vitest-Cases). Confirm-Button bleibt disabled bis Reason valid. Pflicht-Pattern für ALLE destruktiven Admin-Aktionen (Suspend, Promote, Demote, Delete). Backend's eigene Reason-Validation ist asymmetrisch: `PATCH /api/admin/users/:id` toleriert leeren reason, `DELETE` erzwingt non-empty — die Client-Min-10-Char-Schwelle ist strenger als beide, was OK ist (UX-Defence).

`/api/me.admin: boolean` ist seit 2026-05-22 die einzige Quelle für die client-side-isAdmin-Entscheidung. Anonymous-User (401) und Network-Errors collapsen beide zu `isAdmin=false` (UX-safe default). Sessions vor dem Bump können das Feld fehlend haben — TypeScript-Client behandelt `undefined` korrekt als false. Backend's `requireAdmin` ist davon unabhängig (liest `account.admin` direkt aus DB pro Request).

## Dark Engineering (Design-System)

Seit dem Redesign 2026-11-18 (Spec `docs/superpowers/specs/2026-11-17-dark-engineering-redesign-design.md`, Plan `docs/superpowers/plans/2026-11-18-dark-engineering-redesign.md`, Mockup unter `docs/superpowers/specs/assets/`) tragen alle vier Oberflächen denselben Look: grünschwarzer Grund mit 160-px-Linienraster und grünem Schein am Seitenfuß, 1-px-Kacheln ohne Schatten, leichte Manrope-Headlines mit `.hl`-Wortteilen in `--accent-text`, Türkis→Mint-Verlaufsbutton für die eine Primäraktion, Segment-Navigation. Hell und dunkel folgen der Systemeinstellung; dunkel ist der Grundzustand. Es ersetzt „Calm Fresh“ (2026-06-03).

- **Eine Token-Quelle**: `design/tokens.css` (nur Custom Properties auf `:root`, dunkel auf bare `:root`, hell in `@media (prefers-color-scheme: light)`). Vite-Oberflächen importieren sie: `viewer/src/styles.css`, `dashboard/src/styles.css`, `sharer/src/styles.css` (`@import "../../design/tokens.css";`). Statische Seiten laden die Kopie `viewer/public/tokens.css` vor `/topbar-footer.css`; die Kopie schreibt `cd viewer && npm run tokens:sync` (Guard `viewer/tests/tokens-sync.test.ts`, `npm run tokens:check`). **Nie** die Kopie von Hand ändern.
- **Tokens**: `--bg` `--panel` `--panel-2` `--line` `--line-soft` `--fg` `--muted` `--accent-text` `--teal` `--mint` `--on-accent` `--glow` `--error` `--warn`, dazu `--font-sans` (Manrope), `--font-mono` (Plex Mono), `--radius` 10px, `--radius-sm` 7px, `--grad-accent`. Text-Hervorhebungen immer `--accent-text` (hell = dunkleres Grün `#087a54`), nie `--mint` — Mint ist für Flächen, Punkte, Ränder. Text auf dem Verlauf immer `--on-accent`.
- **Geteilte Chrome**: `viewer/public/site-chrome.css` (Fonts, Seitengrund, Topbar, Hilfe-Modal, Footer, `.hl` `.eyebrow` `.btn-primary` `.btn-secondary` `.chip` `.tile` `.donate-btn`). Statische Seiten bekommen sie per `@import` aus `topbar-footer.css`, die Viewer-App bündelt sie per Vite-`@import`. Eine Datei statt zweier handgepflegter Spiegel.
- **Guard** `viewer/tests/design-system-guard.test.ts`: jede gelistete Stylesheet-Datei (`SURFACES`) hat keinen eigenen Hell/Dunkel-Schalter, keine alten Token-Namen (`--paper`, `--brand*`, `--ink*`, `--surface` …), keine farbwertigen Custom Properties und Fokusringe in `--fg` (Ausnahme: Video-Overlay-Bedienelemente, weiß auf fester dunkler Fläche). Zusätzlich: `prefers-color-scheme` steht nur in den Token-Dateien (theme-color-Metas ausgenommen). Neue Oberfläche → in `SURFACES` eintragen.
- **Kontrast-Guard** `viewer/tests/design-tokens.test.ts`: `--fg`/`--muted`/`--accent-text` auf `--bg` und `--panel`, `--on-accent` auf `--teal` und `--mint`, `--error`/`--warn` auf `--bg` — je ≥ 4,5:1 in beiden Modi.
- **Literale Farben** sind nur erlaubt, wo sie nicht vom Modus abhängen: Markenfarben der Zahlungsanbieter in `.donate-dot`, Video-Overlays (dunkel transluzent über dem Bild), `#000` hinter dem Video.
- **Fonts self-hosted** (SIL OFL, aus `@fontsource/manrope`, Datei-Kopie, keine Dependency): `Manrope-{300,400,500,600}.woff2` + `Manrope-OFL.txt` und `IBMPlexMono-{Regular,Medium}.woff2` je unter `viewer/public/fonts/`, `dashboard/public/fonts/`, `sharer/public/fonts/` (eigene Asset-Sets). Guard `viewer/tests/fonts.test.ts`.
- **Icon A** (Matrix-Monitor): Quelle `sharer/src-tauri/icons/app-icon.svg`, Hex-Glyphen als Sieben-Segment-Rechtecke (kein `<text>`). Byte-gleiche Kopien als `brand-mark.svg` in `viewer/public`, `dashboard/public`, `sharer/public` (Logo per CSS-Hintergrund). Sharer-Raster via `npx tauri icon`, Favicons per `rsvg-convert`. Guard `viewer/tests/icons.test.ts`.
- **Spenden**: Buy me a coffee + PayPal (`https://www.paypal.com/paypalme/mroedig`) im Footer jeder Website-Seite, Kaffee-Button in der Topbar, Spendenstreifen auf der Startseite, beide im Sharer-Info-Tab (Opener-Scope in `sharer/src-tauri/capabilities/default.json`, Rust-Test pinnt die Liste). Dashboard: keine neuen.
- **Class-Name-Preservation** gilt weiter: Tests fragen IDs und Klassen ab; neue Klassen nur additiv.
