# Sharer 0.6.1 — Diagnose-Logging, Code-Ablauf-UX & Hotkey-Härtung

**Datum:** 2026-06-22
**Status:** Approved (Design)
**Auslöser:** Prod-0.6.0-Windows-Build meldet beim Streamen „Streamen konnte nicht
gestartet werden. Bitte erneut versuchen." — nicht diagnostizierbar, weil
Release-Builds kein Log schreiben.

## Problemanalyse (verifiziert)

1. **Keine Diagnose im Release.** Die UI-Meldung (`sharer/src/main.ts:414`/`:525`)
   ist ein generischer Sammel-Fehler für jeden `start_streaming`-Reject. Die echte
   Ursache schreibt `dbg_log()`, das jedoch `#[cfg(debug_assertions)]` ist
   (`lib.rs:42-58`) → im Release ein No-Op. Deshalb existiert keine
   `%TEMP%\auffi-debug.log`.
2. **Windows-Release-CI war kaputt.** Der `Build Sharer (Windows)`-Job für den Tag
   `v0.6.0` ist fehlgeschlagen (Run 27601040410). `build.rs` braucht libvpx via
   vcpkg auf Windows (`find_package("libvpx").expect(...)`), der
   `vcpkg install libvpx`-Schritt + `VCPKGRS_TRIPLET` kamen erst **nach** v0.6.0 in
   `build-sharer.yml`. Die auf auffi.app servierte 0.6.0-`.exe` hat damit
   zweifelhafte Herkunft. Auf `main` bereits repariert.
3. **Latenter Hotkey-Bug.** `hotkey::register_pause_hotkey(...)?` (`lib.rs:481`)
   bricht via `?` den gesamten Stream ab, wenn die globale Tastenkombination
   `Ctrl+Alt+P`/`Ctrl+Alt+Pause` bereits von einer anderen App belegt ist — ein
   Komfort-Hotkey darf Streaming nie killen. Top-Verdachtskandidat für den Fehler.

## Scope

### 1. Diagnose-Logging (runtime-gated)

- `dbg_log` von compile-time auf runtime-gated umstellen:
  `static DEBUG_LOGGING: AtomicBool = AtomicBool::new(cfg!(debug_assertions))`.
  Dev-Builds → Default an (unverändertes Verhalten); Release → Default aus.
  Sicherheits-Eigenschaft bleibt: die welt-schreibbare Temp-Datei wird nur
  angelegt, wenn explizit aktiviert (TOCTOU-Symlink-Hinweis im Doc-Kommentar
  aktualisieren).
- Eine einzige `dbg_log`-Definition (kein `cfg`-Split mehr); jede Zeile mit
  Zeitstempel.
- Aktivierung: (a) CLI-Flag `--debug` beim Start, (b) Einstellungen-Schalter
  (persistiert via `tauri-plugin-store`, beim Start gelesen). Effektiv:
  `--debug` ODER gespeicherte Einstellung.
- Mehr Logging an bisher stummen Stellen in `start_streaming`: OS/Monitor-Info,
  peer::new-, Capture-, Encoder-, Hotkey-, ICE-Count-Ergebnisse.
- Neue Tauri-Commands: `set_debug_logging(enabled)` (persistiert + flippt Atomic),
  `get_debug_logging()` (Initialzustand für Toggle), `open_debug_log()` (öffnet
  `%TEMP%\auffi-debug.log` via Shell-Plugin).
- Einstellungen-UI (Abschnitt „Darstellung"): Toggle „Diagnose-Protokoll
  aktivieren" + Button „Log-Datei öffnen".

### 2. Hotkey-Härtung

- `register_pause_hotkey` in `start_streaming` best-effort aufrufen: bei Fehler
  `log::warn!` + `dbg_log`, Stream läuft weiter.

### 3. Code-Ablauf-UX

- Rust: `expiresInSec` durchreichen — `protocol.rs`
  (`_expires_in_sec` → `expires_in_sec`), `signaling.rs` (im `code-assigned`-Emit
  als `expiresInSec` mitschicken).
- Webview: reines Helfer-Modul `sharer/src/code-expiry.ts`
  (`formatRemaining(sec): string` → „9:58"/„abgelaufen"; unit-getestet).
  `main.ts` startet beim `code-assigned` einen Sekunden-Countdown, zeigt die
  Restzeit unter dem Code, graut bei 0 den Code aus („abgelaufen") und hebt den
  Refresh-Button hervor. Timer wird bei neuem Code / Disconnect / Peer-Join
  sauber zurückgesetzt (kein Leak mehrerer Intervalle).
- `#new-code-btn` sichtbar, sobald ein Code angezeigt wird (in `showCode()`);
  versteckt während aktivem Streaming und ohne Code.

### 4. Windows-Release-Pipeline

- Vollständigkeit der bereits auf `main` gelandeten Fixes verifizieren
  (vcpkg-libvpx + gstreamer). Kein erneuter Fix, falls vollständig.

### 5. Version → 0.6.1

- `sharer/src-tauri/Cargo.toml`, `sharer/src-tauri/tauri.conf.json`,
  `sharer/package.json`.

  - `Auffi_0.6.1_x64-setup.exe` (NSIS-Installer aus
    `target/release/bundle/nsis/`)
